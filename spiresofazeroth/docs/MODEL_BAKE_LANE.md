Vanilla creature models come from the LOCAL classic-era game client (1.15.9.70003, `C:\Program Files (x86)\World of Warcraft`, product `wow_classic_era`) via TACTTool; all creature M2s have inline animation keys (no .anim/.skel files), so the existing `m2_anim_glb.build_anim_glb` exports idle/attack/death with no changes. 11 creatures baked in 1.4 s total (extract 0.6 s + 0.02-0.19 s per GLB).

## Facts (verified)
- a) `tools/datamine/m2_anim_glb.py` (main checkout wowgoldfarms) writes a skinned GLB with one glTF animation per `animId:name` pair. It supports ONLY sequences with the inline flag 0x20 (raises for external .anim). Classic-era creature M2s: Stand 0, Death 1, AttackUnarmed 16, Attack1H 17 (+Walk 4, Run 5) are all inline on all 11 test models. Inputs: `.m2`, its first `.skin`, textures `.blp`; replaceable texture slots are filled by `tex_paths[-11/-12/-13]` (monster skin 1-3) and `tex_paths[-1]` (humanoid body skin). Output is JPEG textures (no WebP/KTX in the tool); `max_tex` lever (we used 512).
- b) Files come from the local CASC via `extract_models.extract_batch` (TACTTool list mode, `--basedir` = the install). `data/datamine/modelcache` does NOT exist on CAPTAIN; we used a scratch cache. Run from the wowgoldfarms repo root (listfile.csv is cwd-relative). Build 2417084b8b041ee120d02d4adf31b0bc / cdn f065eade5276a5ac05606e60a4c5a1f7 (`.build.info`, classic era row).
- c) DB `datamine.creature_display_info` (build_seen_id 10260 = wow_classic_era 1.15.9.70003): 11,449 displays, 11,445 with a model, 581 distinct model fdids, 7,392 have `extendeddisplayinfoid` (humanoid baked skins), 371 have no texture and no extra. Chain: `creature_display_info.model_id -> creature_model_data.file_data_id` (= m2 fdid); `raw->>'texturevariationfiledataid'` (pipe list = replaceable 11/12/13); humanoids: `raw->>'extendeddisplayinfoid' -> creature_display_info_extra.raw->>'bakematerialresourcesid' -> texture_file_data(build 16630).file_data_id` = body skin blp.
- **BLOCKER (main finding): npcId -> displayId is NOT in any client table or in the DB.** `datamine.creature` is retail Creature.db2 (sparse, 138 named rows < id 20000; none of 6/100/257/299/448/589 present); `journal_encounter_creature` is retail dungeon bosses only. Classic creature_template is server-side. Source used: Wowhead classic npc page `https://www.wowhead.com/classic/npc=<id>` -> `data-mv-display-id="N"` (sequential, 0.8 s sleep, no 429 seen in 25 hits), and name -> id via `https://www.wowhead.com/classic/search/suggestions-template?q=<name>` (JSON, type 1 = NPC). Scripts: scratchpad `wh.py` (not committed; trivial urllib).
- **Roster reality**: `data/zones/*.enemies.json` holds 1,212 enemy rows / 1,113 distinct names, and only 34 rows have an `npcId` (the brief said 1,686; the file says 1,212). So resolution must be name -> npcId -> display. Also data bug: `Young Wolf` is tagged npcId 69, but 69 = Timber Wolf; Young Wolf = 299.
- Humanoids (human/troll player-race skeletons) are NOT self-textured: need the `bake` skin chain above (Defias/Scarlet/Skullsplitter). Heads are bald/no hair (geosets default); acceptable at card size.
- Some displays (e.g. 167 Forest Troll Berserker on troll.m2) have zero textures in the DB and bake white; fall back to a sibling display of the same model with a non-zero texture, or flag for manual pick.

## Full-roster plan
1. Name -> npcId: Wowhead suggestions API for 1,113 distinct names (~0.7 s each, ~13 min, cache to JSON, review multi-hits; prefer the lowest id that is not "[UNUSED]"/SoD "Season of Discovery" subtitle). Fix 34 existing npcIds (Young Wolf).
2. npcId -> displayId: Wowhead npc pages (~1 s each, ~20 min sequential; NEVER a fleet). Wowhead lists several displays for some npcs; take the first.
3. SQL per display (one bounded query, list of ids): model fdid, texture variation, extra -> bake skin fdid. Expect ~600-800 distinct displays for the roster (581 model fdids exist in the whole classic client) - to be counted exactly after step 2.
4. `bake_roster.py` over the manifest: ~0.1 s per GLB, whole run < 5 min. Key GLBs by DISPLAY id (shared by many npcs), add npcId->display map in index.json (script currently keys by npcId: change one line).
5. Budget: current output averages ~240 KB (max_tex 512). 700 displays ~170 MB: too much to ship at once. Levers: `max_tex 256` + jpeg_q 70 (about half), lazy-load only the GLB for the current encounter (2-5 per fight), cap 400 KB, drop unused LOD. Per-zone lazy loading makes total size irrelevant to page weight.
6. Texture-less/white displays (371 in DB, plus those hitting step-3 fallback) get a sibling-texture fallback or keep the 2D icon.
Estimate: ~1.5 h Claude time for steps 1-4 (mostly sequential Wowhead throttling), +1 h for visual QA via bake-check grids and fixing white/bald outliers.
